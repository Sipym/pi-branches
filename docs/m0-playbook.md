# M0 手工验证 Playbook

目的：零代码验证"节点 fork → 并行提问 → 讨论 → 摘要 → 贴回主线"的体验假设，产出痛点清单反哺设计（design.md §10 M0）。

## 前置

- pi 运行在 tmux 内（`echo $TMUX` 非空）
- 脚本：`scripts/m0-ask.sh`（在主会话的 bash 工具里调用，自动取 `$PI_SESSION_ID`）

## 步骤

1. **开分支**：在主会话让 agent 执行 `bash /path/to/m0-ask.sh "问题一" q1`，可连开多个（q1/q2/q3）
2. **切过去**：`tmux select-window -t branches-<短id>`（或 prefix + `)` 到该 window）
3. **贴定位消息**（M0 无 child 扩展，手动版身份注入，治痛点 #4）：
   ```
   [分支定位] 你是主会话的分支会话(q1)，fork 自当前节点，只讨论：<问题>。
   结束时：值得回主线我会发总结指令（可指定聚焦视角）；纯答疑则我直接退出，无需总结。
   ```
4. **多轮讨论**：像普通会话一样追问，验证"上下文确实是 fork 点的内容"
5. **要摘要**：结束时发：`请把本次讨论压缩成 ≤5 条自包含要点，面向主会话读者，不要过程性废话`；可在指令前附聚焦要求（如"以××为核心"，对应正式版 `/done <聚焦指令>`）
6. **回填**：复制摘要，切回主窗口，作为一条普通消息粘贴发送（⚠️ 记录此痛点）；纯答疑分支跳过 5-6 直接退出（= 手动 `/drop`）
7. **归档**：子 pane 直接退出即可；session 永久保留（`pi --session m0-<短id>-q1` 可找回）

## 验证 Checklist（对应 design 验证标准）

- [ ] 一条命令开出一个 fork pane，落在专用 window，主窗口焦点未被抢
- [ ] fork pane 的上下文从当前节点开始（它"知道"主线聊了什么）
- [ ] 2–3 个问题并行，互不干扰，主会话不被打扰
- [ ] 多轮追问体验正常
- [ ] 摘要贴回后，主会话只增加摘要体积，上下文保持干净
- [ ] 子会话退出后再进（`pi --session`）可续聊

## 成本提示

fork = 入口复制全量上下文。当前主会话较长时，可在脚本里给 `pi --fork` 追加 `--model <轻量模型>` 降低讨论成本（`pi --list-models` 查看）。
